# MD Emporium

A growing collection of focused Markdown missions for working through real-world tasks with an AI agent, practicing technical interviews, and building repeatable workflows.

Each mission is organized around a concrete goal or problem. It gives the agent or practice partner enough context to investigate, reason from evidence, take an appropriate action, and verify the outcome.

## Missions

### Kubernetes

- [Diagnose a Pending Pod](kubernetes/diagnose-pending-pods.md) — an agent-facing troubleshooting mission for pod scheduling and setup problems.
- [kubectl: Interview Essentials](kubernetes/kubectl-commands.md) — a compact command guide for interview practice.

## Human-readable examples

- [kubectl field guide](examples/kubernetes/kubectl-commands.html) — a browsable reference with commands grouped by use case, what to look for, and useful next checks.

Missions give an AI agent the task and working method. Examples provide material to read, adapt, and discuss together.

## Using a mission

1. Open a mission and provide it to your AI agent or interview practice partner.
2. Supply the environment details and outputs the mission asks for. For practice, ask for a simulated scenario when you do not have a real environment.
3. Work from evidence: state a hypothesis, run a diagnostic that can distinguish it from alternatives, and explain what the result means.
4. Agree on any change before applying it, then verify the result against the mission's completion criteria.

Missions are starting points, not substitutes for the relevant system documentation or your organization's procedures. Treat generated or simulated output as such, and avoid sharing credentials or sensitive data.

## Contributing

Focused, reusable missions and human-readable examples are welcome. Keep each mission centered on one goal or problem, use clear steps and verifiable completion criteria, and link authoritative references for technical claims. Prefer concise examples that can be adapted safely.
